# 电商数仓项目需求文档

---

## 一、项目背景

随着电商业务快速发展，业务数据分散在MySQL业务库中，无法直接支撑数据分析和决策需求。
需要搭建一套离线数据仓库，将业务数据统一采集、清洗、汇总，最终输出各类统计报表。

## 二、业务目标

1. 整合业务系统数据，建立统一的数据分析底座
2. 提供多维度（用户、商品、渠道、地区）的经营分析报表
3. 支撑运营、产品、管理层的日常决策

## 三、数据来源

| 数据类型 | 来源 | 采集方式 |
|---|---|---|
| 业务数据 | MySQL业务库 | 全量DataX / 增量Maxwell+Kafka |
| 日志数据 | 用户埋点 | Flume采集 |

## 四、核心分析主题

### 1. 流量域
- 各渠道流量统计（UV、PV、平均停留时长、跳出率）
- 页面路径分析（用户从哪来、到哪去）

### 2. 用户域
- 用户新增、活跃统计
- 用户留存率（次日、7日、30日）
- 用户流失、回流分析
- 用户行为漏斗（浏览→加购→下单→支付）

### 3. 交易域
- 订单统计（下单数、下单金额、下单用户数）
- 支付统计（支付金额、支付时长、支付用户数）
- 品牌交易统计、品类交易统计
- 复购率分析
- 连续下单用户统计

### 4. 商品域
- 品类加购Top3
- 品牌收藏Top3

### 5. 地区域
- 各省份交易统计

## 五、技术选型

| 组件 | 用途 |
|---|---|
| Hadoop HDFS | 分布式存储 |
| Hive | 数仓计算引擎 |
| DataX | 全量数据同步 |
| Maxwell | binlog采集 |
| Kafka | 数据缓冲队列 |
| Flume | 日志采集 |
| MySQL | ADS层数据落地 |
| Superset / Tableau | 可视化报表 |

## 六、交付物

1. 完整的离线数仓五层架构（ODS/DIM/DWD/DWS/ADS）
2. 60+张数据仓库表
3. 16张应用层统计报表
4. 每日定时跑批调度流程
