## 二、ODS层设计

### 2.1 设计原则
- 原样保留业务数据，不做清洗
- 全量表用DataX每天全量同步
- 增量表监听binlog，只同步变化数据

### 2.2 表分类
| 类型 | 数量 | 特点 |
|---|---|---|
| 全量表（_full） | 10张 | 数据量小、会被修改（用户、商品、品类） |
| 增量表（_inc） | 21张 | 数据量大、只增不改（订单、支付、日志） |

---

## 三、DIM层设计

### 3.1 设计原则
- 维度数据统一管理，避免上层重复join
- 小维度做退化，直接冗余到事实表
- 需要历史变化的维度用拉链表

### 3.2 拉链表设计（dim_user_zip）
用start_date和end_date标记每条记录的生效时间：
- 当前有效记录end_date = '9999-12-31'
- 历史记录end_date = 失效日期
- 查某一天的状态：`start_date <= 日期 and end_date > 日期`

![image-20261108165936455](C:/Users/zyql/AppData/Roaming/Typora/typora-user-images/image-20261108165936455.png)

### 3.3 维度退化
- 小维度（支付类型、来源类型）不单独建维度表
- DWD装载时直接关联字典表，把编码+名称一起冗余到事实表
- 好处：减少join，提升查询性能

## 四、DWD层设计

### 4.1 事实表三种类型
| 类型 | 说明 | 项目例子 |
|---|---|---|
| 事务事实表 | 一次业务动作写一行，不回头改 | 下单、支付、注册、加购、收藏 |
| 周期快照表 | 每天存一份全量快照 | 购物车 |
| 累积快照表 | 一个业务一行，多个时间戳 | 优惠券使用 |

### 4.2 数据清洗规则
1. 过滤无效数据（测试数据、未支付订单）
2. 字段对齐、类型统一
3. 敏感信息脱敏（手机号中间打星、姓名只留姓）
4. 空值处理（nvl补0）
5. 关联维度表补名称

## 五、DWS层设计

### 5.1 三种汇总粒度
| 类型 | 说明 | 项目数量 |
|---|---|---|
| 1d表 | 每天一份，按用户/商品/渠道聚合 | 9张 |
| nd表 | 滚动窗口（7天、30天） | 2张 |
| td表 | 累计快照（从项目上线开始累计） | 2张 |

### 5.2 nd表 vs td表
- nd表（滚动窗口）：每天重算整个窗口，因为窗口会滑动，老数据会被踢出去
- td表（累计快照）：只增不减，可以昨天累计 + 今天新增做增量

## 六、ADS层设计

### 6.1 设计特点
- 全部来自DWS层汇总表，不再扫明细
- 用TextFile行存，因为要导出到MySQL做报表
- 不分区，每天用union全量重写，保证幂等

### 6.2 16张应用表分类
| 主题 | 数量 | 表名 |
|---|---|---|
| 流量域 | 2张 | 渠道流量统计、页面路径分析 |
| 用户域 | 4张 | 用户新增活跃、留存率、流失回流、行为漏斗 |
| 交易域 | 7张 | 新增下单、连续下单、品牌交易、品牌复购、品类交易、下单到支付时长、省份交易 |
| 商品域 | 3张 | 品类加购Top3、品牌收藏Top3、优惠券统计 |

## 七、每日跑批流程

```
凌晨2点：
1. 采集当天业务数据到ODS
2. 跑DIM层（拉链表更新、全量维度覆盖）
3. 跑DWD层（清洗明细数据）
4. 跑DWS层（汇总轻度聚合）
5. 跑ADS层（生成最终报表数据）
6. DataX导出ADS到MySQL
7. 报表平台自动刷新
```

## 八、关键技术点汇总

| 技术点 | 说明 |
|---|---|
| 拉链表 | 保存维度历史变化，节省空间 |
| 维度退化 | 小维度冗余到事实表，减少join |
| 动态分区 | 多表join后字段必须加表别名，否则分区值null |
| nd表重算 | 滚动窗口每天重算，不能做增量 |
| td表增量 | 累计表只增不减，昨天累计+今天新增 |
| explode炸裂 | 一行炸成多行，求最近n天数据时减少union |
| mapjoin优化 | 小表做mapjoin，减少shuffle |
